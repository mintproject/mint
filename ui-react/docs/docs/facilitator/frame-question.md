# Frame a question

The source guide describes a problem statement containing tasks and working threads. Prepare a goal, region, time period, desired outcome, and any driver you want to investigate.

Planned walkthrough: create or reopen a problem statement, add a task/thread, and review the framing before resource selection. Exact labels and prerequisites remain to be verified.

## Existing problem statements

**Modeling → Problem Statements** lists the statements already created. Choose a region to narrow the list or search by name; each card shows its task, sub-task and model counts, its time period, and who last updated it. Use **Add** to start a new one. You must be signed in.

## Start a new problem statement

Select **Add** on the Problem Statements page. The setup begins with one short form, and each field changes what you are recommended afterwards.

![The Start model setup form: the question, the model output, region, and dates](../assets/images/problem-start.png)

- **What are you trying to understand, predict, or decide?** Required. Write the real question in plain words, such as "understand seasonal groundwater availability". It names the thread later and is what colleagues will read.
- **What should the model produce?** Optional, but it improves the result. The form says it helps identify the response variable and the models that can produce it. A concrete answer, such as "groundwater hydraulic head" or "flood extent", lets the catalog match models whose registered outputs have that variable. Leaving it blank gives the catalog less to go on.
- **Region:** required. Models and data are tied to regions, so choose the area your question is really about. A region that is too small can leave out useful resources.
- **Start date and End date:** required. Datasets declare their time coverage, so match the window to the period you care about.

Then select **Find recommendations**. Recommendations are only as good as the metadata that model authors and data providers registered. If something you expected is missing, it is often a registration gap rather than a mistake in your question. See [Why metadata matters](../reference/why-metadata.md).
